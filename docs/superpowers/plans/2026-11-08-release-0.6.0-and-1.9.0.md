# Release: desktop 0.6.0, Apple 1.9.0, Android 1.9.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship desktop 0.6.0 (PyPI + signed, notarized DMG), iOS and macOS 1.9.0 (App Store Connect) and Android 1.9.0 (Google Play) from one master commit.

**Architecture:** Each code task is its own branch and PR off `master`, closed with `/finalcheck` (review, fix, CI green), and merged before the next phase. Phase 1 (Tasks 1–7) holds the code fixes; they don't depend on each other and can run in parallel. Phase 2 (Task 8) waits for the maintainer to publish bmlib 0.13.0. Phase 3 (Tasks 9–10) writes the changelog and bumps the versions. Phase 4 (Task 11) builds, tags and publishes.

**Tech Stack:** Python 3.12 / PySide6 <6.12 / hatch / PyInstaller; Swift / SwiftData / Xcode; Kotlin / Gradle / R8; bmlib (PyPI) and bmlib-ffi (UniFFI, committed xcframework).

**Spec:** this conversation's release triage (2026-11-08), summarised in Global Constraints below.

## Global Constraints

- Versions: desktop `0.6.0`; Apple `MARKETING_VERSION = 1.9.0`, `CURRENT_PROJECT_VERSION = 1` (iOS and macOS share one number); Android `versionName = "1.9.0"`, `versionCode = 4`.
- Desktop bmlib dependency: `bmlib>=0.13.0`, taken from PyPI; no git or direct references, because PyPI refuses them.
- Mobile bmlib FFI pin stays at `aa47a57a1e5efb1241be864a01a6eb9d6ea9bda3` (`Packages/BioMedLit/Frameworks/BmlibFFI.pin.json`); don't regenerate the xcframework or the Kotlin bindings.
- `PySide6>=6.6.0,<6.12` stays (#516).
- Channels: desktop on PyPI plus a DMG on the GitHub release; iOS and macOS through App Store Connect; Android as an AAB on Google Play.
- Lint gate: no new ruff/mypy findings against the merge base (`.github/scripts/lint_delta.py`).
- Commit/PR text: no closing keyword before an issue number that should stay open; write "Fixes #N" only for the issue the PR fixes.
- Every tag is cut from a `master` commit on which Python, Swift, Android and bmlib-xcframework CI are all green.

## Review Focus

1. **The release APK crashes where the debug build doesn't.** R8 strips or renames classes reached by reflection (kotlinx.serialization, Retrofit, Room, JNA/UniFFI). Task 5 tests the minified build on an emulator with a fact check that reaches the Rust JATS reader.
2. **An iOS user upgrading from the App Store's 1.6 loses their sessions or crashes at launch.** Since `appstore_1.6`, five optional stored properties and a new retraction-check model were added, and no `SchemaV3` exists (#289). Task 11 installs 1.6, creates a session, then installs 1.9.0 over it.
3. **The DMG only works on the machine that built it.** It might rely on a Homebrew Qt or the dev venv, or Gatekeeper might refuse the QtWebEngine helper. Task 7 opens it from a second macOS user account, after notarization.
4. **Old databases keep their orphaned vectors after the #592 fix.** Rows written by 0.5.0 already have them. Task 4 sweeps them on open and tests against a store built the old way.
5. **A clean `pip install bmlibrarian-lite==0.6.0` doesn't resolve or start.** It may pull a bmlib missing `find_passage`'s guard or `retraction_status`. Task 11 installs into a fresh venv from PyPI and runs `bmll -v validate` and the GUI.

### Task 3: No credential in error text shown to the reader (#330)

**Files:**
- Modify: `src/bmlibrarian_lite/analysis_failures.py` (new `redact_secrets`; `also_failed_text` at line 267 uses it)
- Modify: `src/bmlibrarian_lite/gui/systematic_review_tab.py:670,688` (`self.error.emit(..., redact_secrets(str(e)))`; the raw text stays in the existing `logger.exception`/log line, which must be there, so add one if it's missing)
- Modify: `src/bmlibrarian_lite/constants.py` (`REDACTED_PLACEHOLDER = "[redacted]"`)
- Test: `tests/test_analysis_failures.py` (extend)

**Interfaces:**
- Produces: `redact_secrets(text: str) -> str` in `analysis_failures.py`, a pure function.

Approach: the reader keeps the error's sense ("Connection refused: http://localhost:11434/api/chat") and loses only the secret. The issue's alternative (classify and show the code's description) needs the exception object, but these call sites only have a string. So redact rather than classify.

- [ ] **Step 1: Write the failing tests.**
  - `test_a_url_query_string_is_redacted`: `redact_secrets("Connection refused: http://localhost:11434/api/chat?key=SECRET")` equals `"Connection refused: http://localhost:11434/api/chat?[redacted]"`.
  - `test_bearer_and_api_key_tokens_are_redacted`: for `"Authorization: Bearer abc.def"`, `"x-api-key: sk-ant-api03-XYZ"` and `"api_key=XYZ"`, `"SECRET"`/`"XYZ"`/`"abc.def"`/`"sk-ant-api03-XYZ"` is not in the output and `"[redacted]"` is.
  - `test_plain_error_text_is_unchanged`: `"Connection refused"` comes back unchanged.
  - `test_also_failed_text_never_shows_the_key`: `"SECRET" not in also_failed_text("...?key=SECRET")` and `also_failed_text("") == ""`.
- [ ] **Step 2: Run:** `pytest tests/test_analysis_failures.py -v -k "redact or also_failed"`. Expected: FAIL (`redact_secrets` not defined).
- [ ] **Step 3: Implement `redact_secrets`** with three compiled regexes, case-insensitive:
  1. A URL query string: `(https?://[^\s?#]+)\?[^\s#]*` → `\1?[redacted]`.
  2. `(bearer\s+)\S+` → `\1[redacted]`.
  3. `((?:x-)?api[-_]?key["']?\s*[:=]\s*["']?)[^\s"',]+` → `\1[redacted]`, plus bare `sk-[A-Za-z0-9_-]{8,}` → `[redacted]`.

  `also_failed_text` returns `f" It also stopped on an error: {redact_secrets(error)}"`.
- [ ] **Step 4: Run** the same command. Expected: PASS. Then run `pytest tests/ -q -k "failures or benchmark"`. Expected: no new failures.
